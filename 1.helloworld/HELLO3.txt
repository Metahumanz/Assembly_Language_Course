
进入 DOSBox-X，切换到 1.helloworld 目录，运行 DEBUG（需已具备 DEBUG.EXE/COM）。

在 DOS 提示符输入（不要输入下面示例中的提示符）：
    DEBUG

进入 DEBUG 后会看到 - 提示符。
逐行输入下面这些命令（每一行按 Enter，前面的 - 是提示符，不要手敲）：

    -E 100 0E 1F BA 0E 01 B4 09 CD 21 B8 00 4C CD 21
    -E 10E 48 65 6C 6C 6F 20 77 6F 72 6C 64 21 0D 0A 24
    -U 100 10D
    -D 10E
    -G=100

预期：输出 Hello world! 并换行。

逐字节理解
从 CS:0100 起（共 14 字节）：

  地址相对偏移   十六进制字节       汇编指令       用途
  0100          0E                 PUSH CS        保存 CS
  0101          1F                 POP DS         DS = CS，便于代码段内访问字符串
  0102          BA 0E 01           MOV DX,010EH   DX 指向字符串所在偏移
  0105          B4 09              MOV AH,09H     DOS 打印 $ 结尾字符串
  0107          CD 21              INT 21H        执行打印
  0109          B8 00 4C           MOV AX,4C00H   准备正常退出
  010C          CD 21              INT 21H        程序退出

从 CS:010E 起（共 15 字节）：
  48 65 6C 6C 6F 20 77 6F 72 6C 64 21 0D 0A 24
   H  e  l  l  o     w  o  r  l  d  !   CR LF $

注意：E 后面的数字是十六进制的机器码字节。这里没有写汇编指令文本。
U：反汇编查看；D：查看内存字节；G=100：从偏移 0100H 执行。

老师给的固定地址示例：
  数据写到 076A:0000：48 65 6C 6C 6F 24  （Hello$）
  代码写到 076B:0000：B8 6A 07 8E D8 BA 02 00 B4 09 CD 21 B8 00 4C CD 21
  然后通过 R CS / R DS / R IP 修改代码段、数据段、指令指针，再 G 执行。

但原版机器码中的 BA 02 00 表示 MOV DX,0002H。
如果字符串真的从 DS:0000 开始，这会从第三个字符 l 打印，结果是 llo 而非 Hello。
理论上的最小修正是将 BA 02 00 改为 BA 00 00，即 MOV DX,0000H。

⚠ 不推荐原样使用 076A/076B：这两个段值是老师当时演示时的具体内存地址，
在另一台计算机或另一次 DEBUG 会话中未必安全，强行改 CS/DS、覆盖固定地址
可能破坏调试程序或 DOS 内存。推荐使用上面的 CS:0100 动态版本。

常见问题
1. 提示 Bad command or file name: DEBUG 未提供，需要准备 DEBUG.EXE/COM。
2. 输出乱码或从中间开始：检查 MOV DX 的偏移地址与字符串起始地址是否一致。
3. 没有输出：检查 INT 21H 前 AH 是否为 09H，字符串末尾是否有 24H（$）。
4. 输出后 DOS 提示符紧贴末尾：字符串中可加入 0DH、0AH 换行。
5. DOS DEBUG 与 VS Code 的调试器不是同一个程序。
