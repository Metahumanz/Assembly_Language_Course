# 作业题目5：递归调用——Fibonacci数列

- 日期：2026-11-06
- 源程序：`FIB100.ASM`（8086/MASM 5.0）、`FIB100_C.c`（Windows x86-64 MinGW GCC）
- 反汇编：`FIB100_C_disasm.txt`（Windows实际生成）、`FIB100_C_disasm_中文注释.txt`（完整注释）、`FIB100_C_disasm_核心注释.txt`（核心函数注释）

## 一、题目要求

键盘输入`n`（1≤n≤100），通过递归求`F(n)`，其中`F(0)=0`、`F(1)=1`、`F(n)=F(n-1)+F(n-2)`。要求使用寄存器、初始化栈空间，单步观察`CALL/RET`时栈空间的变化，并用C语言实现、反汇编及添加注释。

## 二、实现方法

1. ASM版的`FIB`是真正的递归子程序：通过`[BP+4]`取得栈传递的参数`n`，依次调用`FIB(n-1)`和`FIB(n-2)`，最后由`RET`逐层返回。
2. 使用`READY`记录已经计算的项，`FIB_TABLE`保存结果。记忆化避免朴素递归对同一项进行大量重复计算，但仍然保留递归调用。
3. `F(100)=354224848179261915075`，超出64位无符号整数范围。ASM版每项用5个16位字（80位）保存，利用`ADD/ADC`处理进位；输出时通过多字除以10转换为十进制。C版使用`unsigned __int128`。
4. ASM版分配4KB栈并设置`SS:SP`。每层`FIB`的主要开销包括参数2B、返回地址2B、旧BP 2B以及4个保存的寄存器8B，共约14B；最深约100层，核心递归栈开销约1400B，4KB留有余量（未将其他调用及中断的临时开销逐项计入）。

## 三、编译与运行

在DOSBox-X中（先进入挂载目录）：

```dos
MASM FIB100.ASM;
LINK FIB100.OBJ;
FIB100
```

在Windows x64 GCC环境中：

```bat
gcc -std=gnu11 -O0 -g -fno-omit-frame-pointer -fno-inline -Wall -Wextra FIB100_C.c -o FIB100_C.exe
FIB100_C.exe
objdump -d -M intel -S FIB100_C.exe > FIB100_C_disasm.txt
```

## 四、调试过程

1. 使用`DEBUG FIB100.EXE`进入调试，输入`R`查看`SS`、`SP`等寄存器；用`U`查看指令，找到`CALL READ_N`、`CALL FIB`。建议先输入`n=5`，便于观察较短的递归过程。
2. 在`CALL FIB`前后和子程序开头的`PUSH BP`前后使用`T`、`R`，观察`SP`逐步减小；使用`D SS:SP`检查栈顶数据。ASM版每次`PUSH`一个16位字或`CALL NEAR`压入返回地址时，`SP`减少2。
3. `MOV BP,SP`建立栈帧后，`[BP]`为旧BP、`[BP+2]`为返回地址、`[BP+4]`为本层递归参数；不同递归层有不同的栈帧。
4. 返回时观察`POP`、`RET`以及调用者执行`ADD SP,2`：被调函数恢复保存的寄存器，`RET`弹出返回地址，调用者清除此前压入的参数，`SP`最终恢复到调用前的位置。

**DOSBox-X实机记录（待填写，不虚构具体数值）：**

- 入口：`SS:SP = ____:____`
- 调用`FIB`前：`SP = ____`

- 执行`PUSH BP`后：`SP = ____`

注意：上述DOSBox-X环境是16位8086，不能直接套用下面Windows x64的`RSP`变化值；Windows x64的返回地址为8字节。

## 六、C反汇编观察与注释要点

以下分析使用**实际生成的Windows x86-64 MinGW GCC反汇编**（`FIB100_C.exe`），而不是此前Linux GCC的参考输出。编译参数为`-O0 -g -fno-omit-frame-pointer -fno-inline`。主要关注`fib`、`print_u128`、`main`，自动生成的MinGW启动及运行库代码不是本题重点。

### 1. `fib`：递归调用与栈帧（入口`140001440`）

```asm
140001440: push rbp                     ; 保存原BP寄存器
140001441: push rbx                     ; 保存被调用者应恢复的RBX
140001442: sub rsp,0x58                ; 分配0x58=88字节栈空间
140001446: lea rbp,[rsp+0x50]         ; 设置本函数的帧基址
14000144b: mov DWORD PTR [rbp+0x20],ecx ; 保存参数n，Windows x64首个整数参数位于ECX
140001458: movzx eax,BYTE PTR [rax+rdx*1] ; 取ready[n]
14000145c: test al,al                 ; 检查该项是否已计算
14000145e: jne 1400014c0              ; 已缓存则直接读取结果
140001468: call 140001440 <fib>       ; 递归求F(n-1)
140001479: call 140001440 <fib>       ; 递归求F(n-2)
140001492: add rax,rcx                ; 两个128位数的低64位相加
140001495: adc rdx,rbx                ; 高64位相加并加上低位进位
14000149b: shl rcx,0x4               ; n*16：每个unsigned __int128占16字节
1400014bc: mov BYTE PTR [rax+rdx*1],0x1 ; 将ready[n]置为1
1400014e4: movdqa xmm0,XMMWORD PTR [rbp-0x30] ; 128位结果放入XMM0返回
1400014e9: add rsp,0x58              ; 释放本层局部栈空间
1400014ed: pop rbx                   ; 恢复RBX
1400014ee: pop rbp                   ; 恢复RBP
1400014ef: ret                       ; 回到上一层调用
```

*上述指令为关键行摘录，省略了中间的取数、暂存和地址计算指令，并非连续可执行代码。* 其中`ADD`与`ADC`一起完成128位整数加法，`CALL 140001440 <fib>`则说明编译结果保留了真实递归调用。此版本用`LEA RBP,[RSP+0x50]`建立帧基址，函数尾用`ADD RSP`、`POP`恢复栈，没有使用`LEAVE`指令。

### 2. `print_u128`：128位整数转十进制（入口`1400014f0`）

```asm
140001551: call 1400028c0 <__umodti3> ; 128位整数对10取余，取得末位数字
140001568: add eax,0x30              ; 数字0~9转换成ASCII字符'0'~'9'
14000156b: sub QWORD PTR [rbp-0x8],0x1 ; 字符指针向前移动一格
1400015a3: call 140002780 <__udivti3> ; 128位整数除以10
1400015b4: jne 140001526             ; 商非零时继续提取下一位
1400015c1: call 140002ce8 <puts>     ; 输出完整十进制数字串
```

128位除法和取模不是直接用一条普通64位`DIV`完成，编译器调用了辅助函数`__udivti3`、`__umodti3`。

### 3. `main`：输入、校验与输出（入口`1400015d1`）

```asm
1400015d1: push rbp                   ; 保存调用者栈帧基址
1400015d2: mov rbp,rsp                ; 建立main栈帧
1400015d5: sub rsp,0x40              ; 分配局部栈空间
1400015e8: call 140002b30 <printf>   ; 输出输入提示
1400015fb: call 140002ae0 <scanf>    ; 读取n
140001600: cmp eax,0x1              ; 判断scanf是否成功读取1项
140001608: test eax,eax             ; 检查n是否为0
14000160f: cmp eax,0x64             ; n与100比较（0x64=100）
140001612: jbe 14000162a            ; 1<=n<=100则进入正常计算流程
14000163e: call 140001440 <fib>      ; 调用递归函数
140001643: movaps XMMWORD PTR [rbp-0x20],xmm0 ; 暂存128位返回值
14000164e: call 1400014f0 <print_u128> ; 输出结果
140001653: mov eax,0x0              ; main返回0
140001658: add rsp,0x40             ; 释放main栈空间
14000165c: pop rbp                  ; 恢复原RBP
14000165d: ret                      ; 返回运行库
```

## 七、学习心得

递归的关键不仅是数学公式，还包括每次`CALL`怎样保存返回地址、如何建立独立栈帧，以及`RET`后怎样恢复现场。记忆化虽然减少重复计算，却没有改变递归调用的结构。通过ASM与C反汇编对照，也看到了8086与Windows x64在参数传递和栈操作上的差别。题目最大输入为100，结果超出64位范围，因此还需要利用`ADC`处理高位进位，并单独实现大整数的十进制输出。
