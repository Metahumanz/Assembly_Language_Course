# SUM：累加求和及栈操作（SUM1.1～SUM3）

## 一、题目与实现

基本目标是计算`1+2+…+100=5050`。先用三种方式保存累加结果，再实现键盘输入`N`的求和，最后用C语言实现并对照反汇编。

| 版本 | 实现内容 | 重点 |
|---|---|---|
| SUM1.1 | 结果保存在寄存器`AX` | `ADD`、循环与寄存器覆盖 |
| SUM1.2 | 结果保存在数据段变量（如`SUMVAL`） | 初始化`DS`，内存地址与小端存储 |
| SUM1.3 | 通过栈保存中间值或结果 | `SS:SP`、`PUSH/POP`、栈平衡 |
| SUM2 | 输入`N`（1～100），求`1+…+N` | ASCII转数值、边界检查、十进制输出 |
| SUM3 | C语言求和并生成x64反汇编 | `for`循环、栈帧局部变量、`CMP/Jcc` |

## 二、编译与调试

在DOSBox-X下可逐个使用`MASM`、`LINK`编译运行。例如：

```dos
MASM SUM2.ASM;
LINK SUM2.OBJ;
SUM2
DEBUG SUM2.EXE
```

`SUM1.1.ASM`等带多个点的旧文件名如不被当前工具接受，可改用`SUM11.ASM`、`SUM12.ASM`、`SUM13.ASM`再汇编，源码中的引用也应对应调整。

调试时用`R`观察寄存器：SUM1.1关注`AX`随循环增长，SUM1.2关注`DS`和变量内存值（用`D DS:偏移`），SUM1.3使用`R`、`D SS:SP`检查压栈和弹栈。8086每次压入或弹出一个16位字，`SP`通常分别减2或加2；尤其要检查`PUSH`和`POP`是否配对，避免破坏返回地址。

SUM2需要逐个检查输入字符：DOS键盘输入得到的是ASCII码，读取十进制数字时需将字符减去`'0'`，然后按“当前值×10＋新数字”累积。SUM3用Windows GCC/objdump：

```bat
gcc -O0 -g -fno-omit-frame-pointer SUM3.c -o SUM3.exe
objdump -d -M intel -S SUM3.exe > SUM3_disasm.txt
```

此前已阅读并注释过SUM3的`main`部分：观察栈上局部变量`i`、`sum`以及循环条件跳转，运行库代码不作为本题主要分析对象。

## 三、结果与检查

| 场景 | 预期结果 | 核对内容 |
|---|---:|---|
| SUM1.1、1.2、1.3 | 5050（`13BAH`） | 三个版本数值一致，存储位置不同 |
| SUM2输入1 | 1 | 最小有效输入 |
| SUM2输入10 | 55 | 两位十进制解析 |
| SUM2输入100 | 5050 | 三位输入、最大边界 |
| SUM2输入0或超出100 | 应按程序设计拒绝 | 非法输入处理 |
| SUM3 | 5050 | C计算结果与反汇编对应 |

`SUM1.2`中的`13BAH`若按字存放，内存低地址先存`BAH`、再存`13H`。对于没有保留的ASM实机记录，本表写的是预期值和核对项目，不冒充已测结果；SUM3曾完成反汇编阅读，具体本机运行截图未随本档保留。

## 四、学习心得

同一个求和任务可以用寄存器、数据段或栈保存结果，但各自的寻址方式和保存现场要求不同。特别是栈版本，需要把`SP`的变化和`CALL/RET`的返回地址联系起来理解。SUM2还说明了输入输出也是程序的一部分：字符与整数不同，必须进行进制转换。C反汇编有助于比较高级语言循环与实际机器指令。
